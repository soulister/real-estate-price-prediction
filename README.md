# Прогнозирование стоимости недвижимости на рынке Москвы

End-to-end ML-проект по оценке рыночной стоимости квартир на основе данных конкурса [Sberbank Russian Housing Market](https://www.kaggle.com/competitions/sberbank-russian-housing-market) (Kaggle). Решение включает исследовательский анализ, feature engineering, гиперпараметрический тюнинг градиентных бустингов, stacking ансамбль и production-like pipeline для инференса.

## Описание проекта

### Цель

Построить модель регрессии, прогнозирующую цену сделки (`price_doc`) по характеристикам объекта, инфраструктуре района и макроэкономическим показателям.

### Бизнес-контекст

Точная оценка стоимости недвижимости — ключевая задача для банков (ипотечное кредитование), девелоперов (ценообразование) и агентств (аналитика рынка). Ошибка в оценке напрямую влияет на риск-менеджмент и маржинальность сделок.

В рамках проекта реализован полный цикл ML-разработки:

- исследование данных и выявление аномалий;
- конструирование признаков с учётом географии и временной динамики рынка;
- сравнение и тюнинг нескольких алгоритмов бустинга;
- построение ансамбля с контролем переобучения;
- упаковка решения в воспроизводимый pipeline с тремя режимами работы.

Метрика качества — **RMSLE** (Root Mean Squared Logarithmic Error), стандартная для данного соревнования.

## EDA и Feature Engineering

Исследовательский анализ выполнен в `notebooks/EDA.ipynb`, разбиение данных — в `notebooks/Train_test_split.ipynb`.

### Ключевые решения

**Временная валидация вместо случайной.** Рынок недвижимости нестационарен: цены зависят от периода сделки. Данные разбиты на 6 временных блоков (`B1`–`B6`) через квантильное разбиение по `timestamp`. Для кросс-валидации используется expanding window: модель обучается на прошлых блоках и валидируется на следующем.

**Очистка аномалий.** Реализована в `src/preprocessing.py`:
- нулевые и противоречивые значения (`life_sq > full_sq`, `floor > max_floor`);
- экстремальные площади и годы постройки;
- приведение макро-категориальных полей к числовому формату.

**Feature engineering** — доменные признаки, отражающие структуру жилья:

| Признак | Смысл |
|---------|-------|
| `living_ratio`, `kitchen_ratio` | Доля жилой / кухонной площади |
| `non_living_sq`, `non_living_ratio` | Нежилая площадь (лоджии, балконы) |
| `sq_per_room`, `life_sq_per_room` | Площадь на комнату |
| `rel_floor`, `is_first_floor`, `is_top_floor` | Позиция квартиры в доме |
| `house_age` | Возраст здания |

**Работа с целевой переменной:** `log1p(price_doc)` на этапе обучения, обратное преобразование `expm1` при инференсе.

**Отбор признаков.** На основе важности признаков в CatBoost, XGBoost и LightGBM (усреднение рангов) отобран топ-300, затем протестированы подмножества размером 100–300. Оптимальный набор — **100 признаков** (`data/features/features_100.json`).

### Гео-признаки

География — один из главных драйверов цены. В финальную модель вошли:

- **`sub_area`** — район Москвы (категориальный признак с высокой предсказательной силой);
- **расстояния до инфраструктуры** — `metro_km_avto`, `school_km`, `preschool_km`, `shopping_centers_km`, `green_zone_km` и др.;
- **транспортная доступность** — `metro_min_avto`, `metro_min_walk`, `railroad_station_avto_km`;
- **близость к транспортным кольцам** — `ttk_km`, `sadovoe_km`;
- **социальная инфраструктура района** — `hospital_beds_raion`, `raion_build_count_with_material_info`;
- **негативные факторы** — `incineration_km`, `industrial_km`, `nuclear_reactor_km`, `radiation_km`.

Объединение с `macro.csv` по `timestamp` добавляет макроэкономический контекст сделки (ставка ипотеки, инфляция, курс рубля).

## Модели

### Сравниваемые алгоритмы

| Модель | Библиотека | Особенности |
|--------|-----------|-------------|
| CatBoost | `catboost` | Нативная работа с категориальными признаками |
| XGBoost | `xgboost` | `enable_categorical=True`, early stopping |
| LightGBM | `lightgbm` | Leaf-wise рост, категориальные фичи |

### Подход к обучению

1. **Baseline** — модели на сырых признаках (`notebooks/baseline_models.ipynb`)
2. **Feature engineering** — добавление доменных признаков, сравнение качества
3. **Feature selection** — отбор топ-100 признаков (`notebooks/features_selecting.ipynb`)
4. **Hyperparameter tuning** — Optuna (TPE sampler, 50 trials на модель) с time-based CV (`notebooks/tuning_results.ipynb`, `src/tuning.py`)
5. **Stacking** — мета-модель Ridge на OOF-предсказаниях базовых моделей

Валидация: 3-fold expanding window CV + отдельный temporal holdout (блок `B6`).

## Финальная модель и pipeline

### Почему Stacking

| Критерий | CatBoost | XGBoost | LightGBM | **Stacking (3 модели)** |
|----------|----------|---------|----------|-------------------------|
| RMSLE (holdout) | 0.32280 | 0.33128 | 0.33230 | **0.32703** |
| Стабильность | Лучший single model | — | — | Усредняет ошибки базовых моделей |
| Обобщение | Риск переобучения на holdout | — | — | Ridge-регуляризация снижает variance |

CatBoost показал лучший результат среди одиночных моделей, однако **stacking из трёх бустингов** выбран как финальное решение по следующим причинам:

- **Стабильность** — ансамбль менее чувствителен к шуму отдельных алгоритмов
- **Устойчивое обобщение** — Ridge-метамодель с L2-регуляризацией (α подобран через Optuna) балансирует вклад каждого бустинга
- **Баланс качества и переобучения** — stacking не гонится за минимальным holdout-score одной модели, а даёт более надёжные предсказания на новых данных

### Архитектура pipeline

```
┌─────────────┐     ┌──────────────────┐     ┌─────────────────────────┐
│  Raw Data   │────▶│  Preprocessing   │────▶│  Feature Engineering    │
│ train/test  │     │  + macro merge   │     │  + 100 selected feats   │
│  + macro    │     │  + anomalies     │     │  + cat encoding         │
└─────────────┘     └──────────────────┘     └───────────┬─────────────┘
                                                           │
                        ┌──────────────────────────────────┼──────────────────────────┐
                        ▼                                  ▼                          ▼
                 ┌─────────────┐                   ┌─────────────┐            ┌─────────────┐
                 │  CatBoost   │                   │  XGBoost    │            │  LightGBM   │
                 │  (tuned)    │                   │  (tuned)    │            │  (tuned)    │
                 └──────┬──────┘                   └──────┬──────┘            └──────┬──────┘
                        │                                  │                          │
                        └──────────────────────────────────┼──────────────────────────┘
                                                           ▼
                                                  ┌─────────────────┐
                                                  │  Ridge Meta     │
                                                  │  (Stacking)     │
                                                  └────────┬────────┘
                                                           ▼
                                                  ┌─────────────────┐
                                                  │  Submission     │
                                                  │  price_doc      │
                                                  └─────────────────┘
```

Оркестратор — `src/pipeline.py`, конфигурация — `config.yaml`.

### Режимы работы

| Режим | Описание |
|-------|----------|
| `predict` | Загрузка сохранённых моделей → предсказание на test → сабмит |
| `retrain` | Переобучение на полном train, пересборка OOF, обучение метамодели → сабмит |
| `retune` | Optuna-тюнинг гиперпараметров на dev → retrain |

```bash
pip install -r requirements.txt
.venv\Scripts\python.exe -m src.pipeline
```

Режим задаётся в `config.yaml` (`mode: predict | retrain | retune`).

| Модуль | Назначение |

| `src/modeling.py` | CV, обучение и сохранение бустингов |

## Geo-анализ (Power BI)

Помимо ML-модели, в рамках проекта выполнен **географический анализ рынка недвижимости** в Power BI.

| | |
|---|---|
| **Файл отчёта** | `reports/geo_visual.pbix` |
| **Исходные данные** | Полный `train.csv` (все сделки обучающей выборки) |

> Рекомендуется скопировать `.pbix` файл в `reports/geo_visual.pbix` для хранения рядом с кодом проекта.

### Что показывает отчёт

- **География цен** — пространственное распределение стоимости квартир по районам Москвы (`sub_area`)
- **Кластеры рынка** — зоны с премиальным, средним и доступным сегментами
- **Инфраструктурный контекст** — связь цены с близостью к метро, социальной и коммерческой инфраструктуре
- **Структура рынка** — плотность сделок, медианные цены, разброс по площади и типу жилья

### Бизнес-ценность

Geo-анализ дополняет ML-модель качественным взглядом на рынок: позволяет визуально верифицировать предсказания модели, выявлять аномальные районы и формировать гипотезы для feature engineering. Для бизнеса это инструмент поддержки решений в ценообразовании, оценке рисков портфеля и выборе локаций для инвестиций.
